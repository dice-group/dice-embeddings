   .. py:method:: predict(*, h: Optional[Union[List[str], str]] = None, r: Optional[Union[List[str], str]] = None, t: Optional[Union[List[str], str]] = None, within: Optional[List[str]] = None, logits: bool = True) -> torch.FloatTensor

      Predict scores for triples or missing triple elements.

      :param h: Head entity/entities. None to predict heads.
      :param r: Relation/relations. None to predict relations.
      :param t: Tail entity/entities. None to predict tails.
      :param within: Optional list of entities to restrict predictions to.
      :param logits: If True, return raw scores. If False, return sigmoid scores (0-1).

      :returns:

                - Single triple (h, r, t): scalar score
                - Missing element: vector of all possible scores
      :rtype: torch.FloatTensor of scores. Shape depends on the query type

      :raises AssertionError: If inputs are not strings or lists of strings.

      .. rubric:: Examples

      >>> # Score a specific triple
      >>> model.predict(h="Mongolia", r="isLocatedIn", t="Asia", logits=False)
      tensor(0.9523)

      >>> # Get scores for all possible tail entities
      >>> model.predict(h="Mongolia", r="isLocatedIn", t=None)
      tensor([0.21, 0.95, 0.03, ...])  # One score per entity

      Predict top-k missing items in a given triple pattern.

   .. py:method:: answer_multi_hop_query(query_type: Optional[str] = None, query: Optional[Tuple[Union[str, Tuple[str, str]], Ellipsis]] = None, queries: Optional[List[Tuple[Union[str, Tuple[str, str]], Ellipsis]]] = None, tnorm: str = 'prod', neg_norm: str = 'standard', lambda_: float = 0.0, k: int = 10, only_scores: bool = False, use_logits: bool = True) -> Union[List[Tuple[str, torch.Tensor]], List[List[Tuple[str, torch.Tensor]]]]

      Answer multi-hop EPFO (Existential Positive First-Order) queries.

      Supports 9 query types: 1p, 2p, 3p, 2i, 3i, ip, pi, 2u, up.
      See docs/guides/multi_hop_queries.md for detailed query patterns.

      :param query_type: Query pattern name. One of:
                         - 1p: (e, (r,))                    # One-hop
                         - 2p: (e, (r1, r2))               # Two-hop
                         - 3p: (e, (r1, r2, r3))           # Three-hop
                         - 2i: ((e1, (r1,)), (e2, (r2,)))  # Two-way intersection
                         - 3i: ((e1, (r1,)), (e2, (r2,)), (e3, (r3,)))  # Three-way intersection
                         - ip: (((e1, (r1,)), (e2, (r2,))), (r3,))  # Intersection + projection
                         - pi: ((e, (r1, r2)), (r3,))                # Projection + intersection (2i meets 2p)
                         - 2u: ((e1, (r1,)), (e2, (r2,)))           # Two-way union
                         - up: ((e, (r1, r2)), (e, (r3,)))          # Union + projection
      :param query: Single query tuple matching the query_type pattern.
      :param queries: Batch of queries. If provided, query must be None.
      :param tnorm: T-norm for intersection/union. Options: "prod", "min".
      :param neg_norm: Negation norm. Options: "standard", "sugeno", "yager".
      :param lambda_: Parameter for sugeno and yager negation (0.0-1.0).
      :param k: Number of top answer entities to return.
      :param only_scores: If True, return only scores tensor. If False, return (entity, score) tuples.
      :param use_logits: If True, use raw model logits. If False, use sigmoid probabilities.

      :returns: List[(entity, score), ...] of top-k answers.
                For batch queries: List of such lists, one per query.
      :rtype: For single query

      :raises ValueError: If query_type is not in {1p, 2p, 3p, 2i, 3i, ip, pi, 2u, up}.
      :raises AssertionError: If query structure doesn't match query_type pattern.

      .. rubric:: Examples

      >>> # 1p: Find entities located in Asia
      >>> model.answer_multi_hop_query(
      ...     query_type="1p",
      ...     query=("Asia", ("isLocatedIn",)),
      ...     k=5
      ... )
      [("Mongolia", 0.92), ("China", 0.89), ...]

      >>> # 2p: Two-hop query (e.g., "capital of countries in Europe")
      >>> model.answer_multi_hop_query(
      ...     query_type="2p",
      ...     query=("Europe", ("isLocatedIn", "hasCapital")),
      ...     k=3
      ... )
      [("Paris", 0.85), ("Berlin", 0.82), ...]

      >>> # 2i: Intersection query
      >>> model.answer_multi_hop_query(
      ...     query_type="2i",
      ...     query=(("Asia", ("isLocatedIn",)), ("Mountains", ("hasGeography",))),
      ...     k=5
      ... )
      [("Nepal", 0.78), ("Tibet", 0.65), ...]

      .. seealso::

         - docs/guides/multi_hop_queries.md: Complete guide with all query patterns
         - tests/test_answer_multi_hop_query.py: Usage examples



   .. py:method:: find_missing_triples(confidence: float, entities: List[str] = None, relations: List[str] = None, topk: int = 10, at_most: int = sys.maxsize) -> Set

               Find missing triples

               Iterative over a set of entities E and a set of relation R :
      orall e \in E and
      orall r \in R f(e,r,x)
               Return (e,r,x)
      ot\in G and  f(e,r,x) > confidence

              Parameter
              ---------
              confidence: float

              A threshold for an output of a sigmoid function given a triple.

              topk: int

              Highest ranked k item to select triples with f(e,r,x) > confidence .

              at_most: int

              Stop after finding at_most missing triples

              Returns: Set
              ---------

              {(e,r,x) | f(e,r,x) > confidence \land (e,r,x)
      ot\in G
